# 性能证据与对标口径

本文件区分文献结果和未来实测。本次仅采集、核查和分析；不存在本机跑出的软件加速比。证据明细见 [CSV](raw_data/性能证据表.csv)，每条含原文定位、硬件、问题、规模、基准和局限。

## 1. 数字应如何解读

### PyFR：强扩展与物理卡数

P01 的 PDF 第17页表2、3提供完整数据，已转录为 [CSV](raw_data/PyFR强扩展原始表.csv)。Frontier 是一张 MI250X 两个 GCD、每 GCD 一个 rank；Alps 是一个 GH200 一个 rank。因此同为2048 ranks，分别对应1024张 MI250X与2048个 GH200。两个测试使用同一 TGV、七次多项式与四面体网格，但 MPI 的设备感知模式不同。

Frontier 的 GDoF/s 从16 ranks的26.21增至2048 ranks的1537.68；Alps从96.07增至5753.96。这里保留论文的吞吐单位，不额外猜测其与“完整时间步所有标量未知量更新次数”的换算。强扩展效率按16 ranks基准分别约46%、47%；Alps中间点略高于100%是原文数据，应保留，不人为截断。

该固定问题最小从16 ranks起算，不能由此宣称存在独立单卡全问题结果。论文中 GH200 与单个 MI250X GCD 的性能比也不等于 GH200 与整张 MI250X 的比。[P01](../ref-paper/fulltext/P01_PyFR_v2.pdf)

### GALÆXI：显式容量与多项式阶次

P02 的 PDF 第13页表2已转录为 [CSV](raw_data/GALAEXI显存原始表.csv)。N=1、3、5、7时分别为1.457、1.049、0.942、0.869 KiB/空间DoF。这里的空间DoF是单个解分量的节点数，内存则包含方程组及辅助数组。随着阶次增大，面/体节点比下降，这是其每空间DoF显存下降的重要原因。

40 GiB容纳约4800万空间DoF是论文对N=7显式配置的示例，不代表任何精度、方程和隐式方案均有该容量。不应将这一结果按显存容量线性缩放后作为HyRES承诺。论文扩展至1024张A100，计时以时间推进为主，排除初始化和分析；在该配置每卡负载约超过10⁶空间DoF时进入较好的扩展区间。[P02](../ref-paper/fulltext/P02_GALAEXI.pdf)

### HORSES3D-GPU：单卡负载和弱扩展基准

P03 的PDF第15–18页使用MareNostrum 5的H100 64 GB HBM2e配置。单卡曲线显示每卡超过16,384单元后接近该阶次测试中最佳吞吐的90%；这不是GPU比CPU快90%，也不是通用最优网格规模。

P=5、每卡16,384六面体、KEP、1000时间步的弱扩展结果，以4卡单节点为基准，256卡约90%。论文另有CRM到2048卡的结果，两者案例和负载不同，不把TGV的90%套到CRM。[P03](../ref-paper/fulltext/P03_HORSES3D_GPU.pdf)

### MFEM：算子/预条件器与多物理应用须分开

P06 的PDF第16页报告LOR预条件研究中的256卡弱扩展：setup约83%、solve约87%。高阶算子作用、低阶组装、AMG setup、AMG V-cycle的瓶颈不同，应分别记录。测试GPU范围4–1024，并不意味着所有阶段在1024卡仍保持同样效率。

P07 的PDF第11页给出MARBL三维shaped-charge应用在12卡上的总显存181→97.3 GB。优化涉及临时分配器、缓冲复用和局部存储溢出；不能将减少量全部归因于“采用MFEM”或“换成RAJA”。[P06](../ref-paper/fulltext/P06_LOR_GPU.pdf)、[P07](../ref-paper/fulltext/P07_MFEM_RAJA.pdf)

### HiFiLES：公开声明完整度不足

[README](../ref-code/HiFiLES/README.md)第23行给出16卡强/弱扩展声明，但没有足够的硬件、网格、阶次、计时及基准定义。相关源稿有FR实现及验证资料，仍不足以恢复一套现代GPU可比测试记录。因此本项可以作为历史能力线索，不能参加严格数值排名。

### 2026 年 GALÆXI AMD/APU 路线

P10 的PDF第3–4页报告MI300A SPX模式：N=9、每APU409.6万空间DoF、10个RK时间步，512 APU的弱扩展效率90.4%，基准单节点。论文另研究了SPX/TPX/CPX分区模式；物理APU数量和逻辑设备数量必须分开记录。现有公开main源码与该论文不一致，故这组结果只作为论文证据。[P10](../ref-paper/fulltext/P10_GALAEXI_APU.pdf)

## 2. 横向对比能回答与不能回答的问题

可以回答：各框架采用何种算子组织；何种负载下启动/通信开销明显；哪些缓冲增加显存；为何需要针对阶次和硬件调优。

目前不能回答：在相同HyRES考核问题、相同硬件/精度/收敛标准下哪个框架最快；某个框架的HIP性能能否直接在曙光DCU上复现；某个显式核加速能否带来同幅度隐式端到端加速。

资料未提供完整数字时，标记“未获得完整可比证据”，不填0、不填推算值，也不把图上粗略读数当成精确表格数据。

## 3. 后续统一测试的最小约定

1. **一致性门槛**：相同方程、物性、边界、初值、网格、空间精度目标、时间区间；记录误差、守恒和收敛轨迹。不同离散方法另做等误差比较，不能只比同节点数。
2. **工作量口径**：同时记录单元数、空间节点数、变量数、标量未知量数、积分点数、RK阶段数和残差评估次数；区分多项式次数p与空间精度阶。
3. **单卡与CPU**：CPU单核、CPU整节点分别列；写清GPU型号、FP64能力、内存带宽、频率、设备模式。精度和停止准则一致后计算加速比。
4. **多卡**：物理卡数、GCD/XCD或逻辑设备数、rank数独立记录。强扩展固定全局问题，弱扩展固定每卡工作量；基准为q₀卡时写明q₀。
5. **计时**：分别记录setup、稳定推进/求解、通信、I/O及总耗时。异步核计时须在测量边界正确同步；重复至少3次，保留原始数据与中位数。不要逐核强制同步破坏待评估的重叠流程。
6. **显存**：应用分配量、设备占用峰值分别采集；保留初始化、首步及稳态峰值。区分GB和GiB，区分节点DoF和标量未知量。隐式计入Krylov基、雅可比和预条件器。
7. **归档**：固定源码SHA、依赖版本、编译选项、驱动、MPI/设备感知设置、输入哈希、标准输出、profiler原始文件。当前[实测模板](raw_data/后续实测记录模板.csv)只有表头，尚无实验数据。

采用q₀卡为基准的强扩展效率：`Es(q) = T(q₀)/T(q) × q₀/q`；固定每卡工作量的弱扩展效率：`Ew(q) = T(q₀)/T(q)`。需要记录时间步数等工作量相同的前提。

若使用PID，推荐明确写为 `T × q / (Nnode × Nsteps × Nstages)`；如果分母使用标量DoF，则指标名称必须随之改变。隐式求解同时记录外迭代、线性迭代及残差评估次数，不能把每迭代更快当作达到相同误差更快。

## 4. 证据等级和引用规则

为避免公开数字被过度使用，本报告将性能证据分为四级：

| 等级 | 定义 | 可用于 | 不可用于 |
|---|---|---|---|
| A | 原始论文给出硬件、问题、规模、计时定义和原始表/公式 | 报告作者在该条件下的结果，设计同类测试 | 直接外推到另一个软件/硬件 |
| B | 原始论文给出曲线或完整方法，但缺少部分原始数据 | 说明趋势、负载阈值和设计原因 | 把图上估读值写成精确性能 |
| C | 官方README或文档给出性能声明，条件不完整 | 作为能力线索，确定补测项目 | 参加严格横向排名 |
| D | 二手文章、搜索摘要、未经核实的演讲材料 | 发现检索方向 | 进入正式性能表 |

当前表格中的 P01/P02/P03/P06/P07/P10 主要属于 A；HiFiLES README 的16卡声明属于 C；没有把搜索摘要数字写入性能表。对同一软件，论文结果和当前源码快照不同步时，引用必须同时写“论文版本”和“源码提交”。

## 5. 从公开结果还原实验变量

一个性能数字至少由下列变量组成：

```text
软件提交 + 编译器/优化选项 + 运行库/驱动
+ 方程/物性/边界/初值 + 网格/单元/阶次
+ 精度 + 时间推进/线性求解 + 设备模式
+ rank/卡/GCD/XCD映射 + 计时边界 + 重复策略
```

缺少任一项时，应把结果标记为“条件不完整”。例如“90%弱扩展”必须同时说明：基准卡数、每卡单元或DoF、总步数、是否含初始化与I/O、MPI设备感知方式和硬件互连。只写百分比会把弱扩展效率误读为绝对利用率。

### 5.1 DoF、节点和未知量

对一个三维六面体、每方向多项式次数为 `p` 的节点型方法，空间节点数为：

```text
Nnode,elem = (p + 1)^3
Nscalar,elem = nvar × (p + 1)^3
```

若使用过积分、面变量、梯度变量、阶段寄存器或线性求解基，实际分配量还要加上：

```text
Nwork = Nvolume + Nsurface + Ngradient + Ngeometry
      + Nstage + Nkrylov + Npreconditioner + Ntemporary
```

因此论文以“空间DoF”计量时，不能乘一个固定的变量数就得到显存；不同实现可能把几何、面值和临时空间计入或排除。记录时应同时保存 `Nnode`、`nvar`、`Nscalar` 及每一类缓冲的字节数。

### 5.2 显式与隐式的工作量

显式一步可按 `Nstage × Tresidual` 统计，其中 `Tresidual` 应包含体、面、边界、通信及必要归约。隐式一步至少要记录：

```text
Timplicit = Tassemble/setup
          + NNewton × (Tlinearize + Nlinear × (Tmatvec + Tprecond + Treduce))
          + Tupdate + Toutput
```

矩阵自由方法的 `Tmatvec` 可能是完整残差线性化的近似作用；解析/自动微分/有限差分 Jacobian 的代价和误差不同。若只报告“单次 Kernel耗时”，无法证明隐式端到端性能。

## 6. 按框架设计统一复测方案

以下不是已经完成的实验，而是将公开结果转换为可复现实验的最小设计。每个框架都应先完成单软件回归，再做跨软件比较。

| 框架 | 第一阶段复测 | 第二阶段扩展 | 必须单独记录的变量 |
|---|---|---|---|
| PyFR | TGV、固定p、单设备、多次稳态步 | 固定全局问题强扩展、固定每卡DoF弱扩展 | CUDA/HIP后端、MPI感知、图开关、SoA块宽、设备GCD |
| GALÆXI | weak/split form分别测单卡 | stream开关、MPI面比例、多卡扩展 | stream同步、MPI设备指针、体积分批大小、N和方程变量 |
| HORSES3D-GPU | `.ns`显式路径及每个支持算例 | 内部面/MPI面比例、OpenACC参数扫描 | compiler、present区域、async队列、对象深拷贝、回传 |
| HiFiLES | GEMM、pointwise、面通信分项 | GPU-direct替代主机中转的A/B | `_GPU`开关、cuBLAS版本、打包时间、MPI等待、回传 |
| MFEM | PA operator apply、LOR预条件、单算子 | setup/apply/solve弱扩展 | AssemblyLevel、D1D/Q1D、Device、Memory allocator、AMG参数 |

每个阶段都应保存：输入文件、网格哈希、源码SHA、构建日志、设备信息、运行日志、profiler报告和原始计时。只有在准确性门槛通过后，才进入性能阶段。

## 7. Kernel级性能指标

### 7.1 时间指标

- `Tlaunch`：Kernel启动及运行时间；异步API必须在同一设备事件上闭合计时。
- `Tmemcpy-H2D/D2H`：主机—设备传输；统一记录同步和异步版本。
- `Tmpi-pack/unpack`：面或halo打包、解包。
- `Tmpi-wait`：MPI请求等待；不能把它隐去在“通信总时间”中。
- `Treduce`：最大波速、范数、残差和点积等全局/局部归约。
- `Tsolver`：线性求解器和预条件器；区分setup、apply和迭代。

### 7.2 硬件指标

至少采集：实际占用显存、内存带宽、L2/缓存命中、SM/CU占用、活动线程束、寄存器数、共享内存、分支分歧、PCIe/NVLink/互连传输量和设备功耗（若可用）。

高阶算子的初步算术强度可用：

```text
AI = FLOPs_kernel / bytes_read_write
```

但 `bytes_read_write` 必须根据实际缓存/共享内存访问和写回统计，不能只按源代码数组大小估计。点通量、面gather、归约和GEMM的 AI 不同，不能用一个平均值解释整个残差。

### 7.3 结果展示建议

同一算例至少给出四张图或四列数据：

1. 总耗时与分项耗时堆叠图；
2. 单设备吞吐随DoF/单元数变化图；
3. 强扩展效率和通信等待占比图；
4. 峰值显存随阶次、变量数、隐式迭代空间变化图。

如果只给加速比柱状图，评审无法判断收益来自计算核、减少迭代、改变网格、减少I/O还是计时边界变化。

## 8. 正确性门槛与性能门槛分离

### 8.1 正确性门槛

- CPU与GPU在同一精度下的解差异满足预设范数阈值；
- 等熵涡、Couette、制造解或任务书算例保持设计收敛阶；
- 质量、动量、能量等守恒量与参考结果一致；
- 隐式求解的残差单调性、迭代次数和停止原因一致；
- 多卡结果与单卡/CPU在允许并行归约误差下相符；
- 重启、输出、边界和异常路径不产生设备/主机数据不一致。

### 8.2 性能门槛

只有正确性门槛通过后，才记录：

- 同一输入重复至少三次的中位数和离散度；
- 首次运行与稳态运行分别记录；
- setup、求解、通信、归约和I/O分开记录；
- 显式与隐式使用各自的完整端到端计时；
- 单精度、双精度和混合精度分开报告误差与速度；
- 多卡强扩展和弱扩展使用明确基准卡数及工作量。

“编译成功”“Kernel运行成功”属于功能检查，不是正确性通过；“单个Kernel加速”属于局部性能，不是端到端性能通过。

## 9. 评审可直接使用的性能记录表

| 记录项 | 最小内容 | 缺失时的风险 |
|---|---|---|
| 版本 | commit、编译器、驱动、MPI、后端库 | 无法复现实验 |
| 算例 | 方程、边界、网格哈希、单元、p、变量数 | 工作量不一致 |
| 数值 | 精度、时间步、停止准则、迭代次数 | 加速比可能来自精度/收敛差异 |
| 设备 | 型号、显存、物理卡、GCD/XCD、rank映射 | 逻辑设备与物理设备混淆 |
| 计时 | setup/Kernel/MPI/solver/I/O/total | 隐藏通信和初始化成本 |
| 显存 | 分配量、峰值、类别、单位GB/GiB | 容量结论不可审查 |
| 正确性 | 误差、守恒、收敛、重启/多卡一致性 | 性能数字没有可信前提 |
| 原始证据 | stdout、profiler、输入、环境、重复run | 只能看到整理后的结论 |

本表与[后续实测记录模板](raw_data/后续实测记录模板.csv)一致；模板目前只有表头，不产生任何虚构结果。
